# 生产质量管理系统（QMS）

面向流程制造（化工磷酸铁）的生产质量管理系统：把 **定标准 → 来料检验 → 过程检验 → 成品检验 → 不合格处理 → 批次追溯 → 报表/SPC → 客户 COA** 串成闭环，与生产批次咬合。

> 本地优先、单机可跑：一条命令建库、一条命令启动，浏览器即用（电脑 + 手机），无需安装客户端。

---

## 功能一览

| 模块 | 能力 |
|---|---|
| 📊 质量总览 / 🖥️ 车间大屏 | KPI、待办、各工序合格率、最近动态（大屏 30 秒自动刷新，深色适配车间电视） |
| 📺 数据大屏（管理层） | 本月/区间合格率、IQC/IPQC/OQC 对比、**供应商来料合格率排名**、各工序合格率、NCR 趋势与原因 TOP、SPC 失控预警汇总，30 秒自动刷新 |
| 📱 手机端 | 浏览器直接用（无需装 App）：≤840px 自动切换 App 式交互——底部 Tab 导航、抽屉菜单、表单纵向铺满、表格横向滑动；顶部「📱 手机访问」可出二维码供扫码进入 |
| 🏭 生产批次 | 班组长完工建批（批号 `YYYYMMDD-STxx-EQxx-NNN-[父批]-班组`）、过程检验（IPQC）、成品检验（OQC）、COA 报告、**放行控制** |
| 📋 检验标准库 | 按"物料/工序 + 检验类型"配检验项与限值，支持**模板复制**（应对 25 物料 × 25 工序量级），修改留痕 |
| 🚚 来料检验 | 到货登记自动出批号 → 取样 → 检验录数 → 系统判定（合格放行 / 不合格自动冻结 + 开 NCR） |
| ⚠️ 不合格处理（NCR） | 拒收退货（采购）/ 让步接收（质量经理审批）/ 报废；检验员不能处置自己检出的不合格 |
| 🔍 批次追溯 | 任意批号一键还原：原料（供应商）→ 各工序（设备/班组/操作人）→ 每张检验单实测值 → COA，**链上不合格红字标源** |
| 📈 统计报表 | 合格率、不合格柏拉图、检验趋势、**SPC 控制图（单值 I-MR，超控制限自动预警）**、Excel 月报导出 |
| 📣 客诉管理 | 投诉登记 → 关联批次/COA → 一键查该批追溯 → 原因分析/纠正措施/回复客户 → **8D 式闭环**（缺项不许关单）；统计未闭环件数 |
| 📜 操作日志 | 谁在何时改了什么（标准/判定/账号/岗位职责/客诉）全留痕，管理员可按用户、动作、关键词、时间筛选 |
| 基础资料 / 账号权限 | 物料/供应商/客户/车间/工序/班组/设备/**部门/职务**（CSV 批量导入）；**分权责管理**：部门 + 职务 → 岗位职责模板自动决定模块权限；账号级微调优先；支持一人多工序（多对多） |
| 🤝 客户侧 | COA 公开展示页（免登录、二维码扫码查看，内容含逐项检验结果与判定） |

## 快速开始（本地体验）

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
python scripts/init_db.py        # 建库 + 全套演示数据（含近30天历史数据）
python main.py                   # 启动：http://localhost:8000
```

演示账号（密码均 `123456`）：`admin` / `qm`（质量经理）/ `qc`（检验员）/ `sampler` / `prodlead`（班组长）/ `buyer` / `store` / `boss` / `qc2` / `prodlead2`。

## 技术栈与架构选择

- **FastAPI + SQLAlchemy + 原生 HTML/JS**（无构建工具、无前端框架，部署简单）
- **SQLite 开发 → MySQL 上线**：仅需切换环境变量 `QMS_DB_URL`，业务代码零改动，配套迁移与校验脚本
- **服务监听 `0.0.0.0`**：车间电脑、手机连同一网络即可访问；生产建议 `uvicorn main:app --workers 4`
- **部署形态**：单机（自备服务器/高配台式机）+ 每日备份保留 30 天

---

## 质量保障

- 六套端到端验收脚本（`scripts/e2e_step*.py`）覆盖：权限与基础资料、标准库、来料闭环、生产/成品检验与 COA、追溯/报表/SPC/大屏、部署能力（备份恢复演练、批量账号、迁移工具、压测、局域网访问）
- 关键防错均有测试断言：不合格批**不能被选为下工序父批**、检验员**不能处置**自己检出的不合格、让步接收须质量经理、放行列表只含合格成品、SPC 越界点确实超出控制限
- 仓库内 `agents.md`：每次改动必须提交 commit，且交付前测试必须全绿
